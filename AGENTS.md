# AGENTS.md

Repo root = `vcte5000/`. All path-relative commands below assume this as the working directory.

## Architecture

- **`backend/`** — Django 4.2.8 ERP (server-rendered + HTMX middleware). **`frontend/`** — Vue 3 + Vite 5 + Tailwind CSS 3 SPA → builds into `backend/static/web/` (base path `/static/web/`); dev server :3000 proxies `/api` + `/media` → :8000.
- `docker-compose.yml`: 5 services — `db` (Postgres 15), `redis`, `backend`, `celery_worker`, `nginx`.
- Python 3.11.9 (`.python-version`). 12 backend apps under `apps/` — import as `apps.<name>`. `apps.api` is **not** in `INSTALLED_APPS` but works because its `urls.py` is imported directly. `apps.payroll` also exists (route `/erp/nominas/`).
- `soportes madrid/` — sample PDF/CSV supporting documents (facturas, extractos bancarios) used by test and simulation scripts.
- `backend/manual/` — user manuals (`manual.html` full manual, `roger.html` operator view). The §20 pipeline scripts (root `test_pipeline_capitulo20.py`, `simulacion_capitulo20.py`) implement "capítulo 20" of that manual.
- Utility scripts (root unless noted): `create_test_purchase.py` (seeds catalog materials + multi-material `CompraMaterial`), `fix_inversion_banco.py` (one-off `InversionInicial` bank repair; header has the staging variant), `backend/create_missing_warranties.py` (backfills `GarantiaVehiculo` for existing sales), `backend/generate_manual.py` / `generate_manual_xhtml2pdf.py` (regenerate `media/manual_eurocar_erp.pdf`; on this Windows machine weasyprint lacks GTK libs — use `generate_manual_xhtml2pdf.py`), `backend/manual/ejemplos/gen_soportes_madrid.py` (regenerates the `soportes madrid/` capítulo-20 PDFs). CLI uploads: `manage.py subir_factura_gasto --pk <id> --pdf <file>` (adjunta factura de proveedor a un `GastoEstructura`), `manage.py subir_imagen_vehiculo --matricula <m> --imagen <file>` (solo `EN_VENTA`).
- Settings in `config/settings/`: `development` (default; SQLite unless `DATABASE_URL`), `staging` (no Redis: locmem cache, Celery eager, WhiteNoise; media local/ephemeral on purpose), `production` (S3 media only if `AWS_STORAGE_BUCKET_NAME`; Redis optional → locmem + eager fallback). Root test scripts set `DJANGO_SETTINGS_MODULE=config.settings.development` themselves.
- Root `README.md` is generic marketing and partially stale (says `cd eurocar`; repo dir is `vcte5000`) — trust this file and the code over it.

Routing (`backend/config/urls.py:7-28`): ERP under `/erp/*`, API at `/api/`, admin at `/admin/`. **Catch-all `spa_index` must stay last** — serves the Vue SPA for unmatched paths.

Frontend CSS changes require a full `npm run build` (Vite → PostCSS → Tailwind). The dev server uses HMR for JS/Vue but can miss Tailwind-only rebuilds.

Agent instruction sources beyond this file: `.claude/skills/` contains TestSprite skills (`testsprite-onboard`, `testsprite-verify`) for automated test generation and verification workflows.

## Key views

- **`/api/*` dual-mode**: returns HTML when `Accept: text/html`, else JSON (`apps/api/urls.py:11` `is_html_request`). Keep both branches working.
- **`/api/*` is fully anonymous**: no DRF viewsets — hand-rolled function views only (`apps/api/urls.py:197-203`): `health/`, `ping/` (plain "OK", no DB), `vehiculos/`, `vehiculos/<pk>/`, `marcas/` (listings filtered to `EN_VENTA` + `precio_venta>0`). DRF's `IsAuthenticated` default doesn't apply to function views; `test_modules.py` asserts `/api/vehiculos/` → 200 unauthenticated — don't "protect" them. El listado devuelve `imagen_url` (portada) **y** `imagenes_urls` (galería ordenada) para el carrusel de las tarjetas; el detalle devuelve `imagenes: [{url, es_principal, orden}]`. Las tarjetas del catálogo y de la home usan `aspect-[4/3]` + `object-cover`, con `loading="lazy"` salvo la portada.
- **SPA works only after `npm run build`**: `spa_index` serves `STATIC_ROOT/web/index.html`, else 404 "Web pública no construida" (`apps/core/views.py:94-100`). Build artifacts (`backend/static/web/`) are git-ignored but **force-committed** (`git add -f`) so the public catalog works at `/` on Render — after ANY frontend change, rebuild and re-commit them. Deep links (`/catalogo`, `/vehiculo/<id>`, `/tasacion`, `/contacto`) hit the `spa_index` catch-all (vue-router history mode).
- **Roles** (`accounts.User.rol`): `ADMIN`, `OPERARIO`, `VENDEDOR`, `GESTORIA`. Use `user.is_admin` / `is_operario` / `is_vendedor` / `is_gestoria` properties — never raw `rol` comparisons.
- **Usuarios en el ERP**: `apps/accounts/views_usuarios.py` + `urls_usuarios.py` sirven `/erp/usuarios/` (listado, alta, edición, activar/desactivar, desbloquear), solo para `is_admin`. El enlace del sidebar «👥 Usuarios» apunta ahí; «⚙️ Admin técnico» sigue siendo el admin de Django. Un ADMIN no puede desactivarse a sí mismo.

## Gotchas

- **Custom User** = `accounts.User` (`AUTH_USER_MODEL`). Import from `apps.accounts.models`, never `django.contrib.auth`.
- **`User.puede_eliminar`** (default True) gates delete permission. `rol` default is `'OPERARIO'` (`accounts/models.py:19`); migration `0003_alter_user_rol` briefly set the DB default to `'ADMIN'` and `0004_alter_user_rol` aligned it back to `'OPERARIO'` — if you add another `AlterField`, keep the model default in sync. The login view auto-repairs empty `rol` to `'ADMIN'` for staff users. `is_admin`/`is_operario`/`is_vendedor`/`is_gestoria` properties also return True for any `is_superuser`, so a `createsuperuser` user passes every role check.
- **Keep `base.py:5-14` monkey-patch** of `BaseContext.__copy__` (Python 3.14 compat even though we run 3.11).
- **`development.py` desactiva explícitamente HTTPS/HSTS** (`SECURE_SSL_REDIRECT=False`, cookies no `Secure`). `base.py` aplica los ajustes de producción cuando el entorno no define `DEBUG`, y un clon sin `backend/.env` provocaría un 301 a HTTPS en el servidor de desarrollo. No quitar ese bloque.
- **`debug_toolbar` removed** — incompatible with Python 3.14. Don't re-add.
- **`.env` split**: `backend/.env` is read by Django (`base.py:23`) y **ya no está versionado** (salió de git; plantilla en `backend/.env.example`). Root `.env.example` is for docker-compose only.
- **Spanish number formats**: `base.py` sets `USE_THOUSAND_SEPARATOR=True` + `FORMAT_MODULE_PATH=['config.formats']` (`config/formats/es/formats.py`: `.` thousands, `,` decimals → `8.294,00`). Templates render amounts in this format; tests asserting exact amount strings must match it.
- **Media en staging vs producción**: `config/urls.py` registra siempre `^media/(?P<path>.*)$` y la vista solo responde si `DEBUG` o `SERVE_MEDIA_LOCAL`. En `staging.py` vale `True` (sin bucket, los PDFs se abren durante las pruebas desde el disco del contenedor, que **se borra en cada redeploy**). En `production.py` vale `False`: la media debe ir a S3/R2. Sin esa ruta, con `DEBUG=False` cualquier adjunto daba 404.
- **Plan contable automático**: `apps/accounting/apps.py` conecta `post_migrate` y crea el PGC (56 cuentas, `get_or_create`) en cada `migrate`. La vista `bank:cuenta_create` lo recrea si está vacío, para que el desplegable «Cuenta contable» nunca aparezca vacío. El botón «Inicializar PGC» se retiró de la interfaz; el endpoint queda solo para mantenimiento y scripts.
- **Dual account locking**: manual (5 attempts → 1h lock) + `django-axes` (`AXES_FAILURE_LIMIT=5`, `AXES_COOLOFF_TIME=1`). Both active.
- **`django-csp`** in `INSTALLED_APPS` (no custom `CSP_*` settings). Default CSP blocks inline `<script>`/`<style>` — use nonces or external files.
- **PDFs** (`apps/sales/services.py`): motor perezoso — WeasyPrint si sus librerías de sistema (Pango/Cairo) cargan; si no, `xhtml2pdf` (Python puro, el que funciona en el runtime nativo de Render, que no instala paquetes del sistema). Los PDFs se guardan vía `FileField`/`default_storage`, nunca escribiendo a `MEDIA_ROOT` a mano, para que funcionen igual con disco local y con S3/R2.
- **Session**: expires in 1h and on browser close. `SESSION_SAVE_EVERY_REQUEST=True`.
- **`django-cleanup`** auto-deletes orphaned files when records are removed.
- **Development** has `AUTH_PASSWORD_VALIDATORS = []` — weak passwords work locally but not in production.
- **`SECRET_KEY` has no default** (`base.py:25`) — local Django runs fail without `backend/.env`; Docker works zero-config (compose supplies an insecure dev fallback). Several migrations (e.g. accounts `0003`, vehicles `0007`) were generated by Django 6.0.7 — never run `makemigrations` with anything newer than the pinned 4.2.8.
- **Production degrades gracefully without Redis** (`production.py`): if the `REDIS_URL` env var is absent, cache falls back to locmem and `CELERY_TASK_ALWAYS_EAGER=True` + broker/result `None` (same pattern as staging). Set `REDIS_URL` on Render only if a Redis instance is actually provisioned.
- **Bank movements** are never created manually — `apps.bank.services.crear_movimiento_banco()` is the single entry point; `BancoCuenta.saldo` is computed on-the-fly. All reconciliation logic (`conciliar_extracto`, `conciliacion_bancaria_sugerencias`, `marcar_conciliado`, `conciliacion_batch`) lives in `apps/bank/services.py`.
- **Vehicle images**: uploads only allowed while `estado='EN_VENTA'`; al salir de `EN_VENTA` las fotos **se conservan** (ocultas, reaparecen al volver) — antes se borraban en silencio. Tope **15 adicionales + 1 principal** (`MAX_IMAGENES` en `apps/vehicles/forms.py`); el formset **avisa** si se supera en vez de recortar en silencio. Toda subida pasa por `apps/vehicles/images.py`: reduce a 2560 px, recomprime en JPEG q85, descarta EXIF y guarda en `vehiculos/<matricula>/`. El campo `ImagenVehiculo.es_principal` sigue en BD pero **no se usa** (la portada es `Vehiculo.imagen_principal`). Procedimiento de usuario: manual capítulo 22.
- **Vehículos: publicación separada y bloqueo contable**. `vehicles:publicar` (`/<pk>/publicar/`, template `vehicles/publicar.html`) edita solo `estado`, `precio_venta`, `descripcion_dano` e imágenes (`VehiculoComercialForm`, que también reduce la portada con `procesar_imagen`); accesible también al rol VENDEDOR y **sin tocar costes ni contabilidad** (el `save()` del modelo recalcula `coste_inicial` con los valores que ya tenía, así que no cambia). **El formulario técnico (`vehicles:update`/`create`, `form.html`) NO tiene campos comerciales** (`precio_venta`, `descripcion_dano`, `imagen_principal` ni el formset de fotos): todo eso vive en Publicar. Cuando el asiento del vehículo está `POSTEADO`, `VehiculoForm.__init__` **saca** los `CAMPOS_FINANCIEROS` de `self.fields` (no los deshabilita) y los expone formateados en `form.datos_bloqueados`; la plantilla los pinta como texto de solo lectura y oculta los fieldsets económicos con `{% if not form.datos_bloqueados %}`. Ojo: `clean()` solo debe rellenar claves que existan en `self.fields`, o Django falla en `construct_instance` (`KeyError`). La vista de edición **no toca el asiento si está POSTEADO**; si está en borrador lo regenera. El guardado va en una transacción con `try/except`: nunca devuelve 500, muestra el motivo y registra la traza con `logger.exception`. **`ImagenVehiculoForm.clean_imagen` solo procesa archivos recién subidos** (`isinstance(archivo, UploadedFile)`): re-procesar un `FieldFile` ya guardado fallaba con `FileNotFoundError` cuando el archivo se había perdido en un despliegue (era el 500 al marcar «Eliminar» una foto antigua). La miniatura usa `ImagenVehiculoForm.url_actual()` (nombre de `initial`, nunca `.url` de un archivo sin guardar). El botón **Quitar** (`vehiculo-publicar.js`) marca el `DELETE` oculto y oculta la fila, o elimina la fila nueva y ajusta `TOTAL_FORMS`. **Importes**: `ImporteField`+`parsear_importe()` aceptan `7.500,00`, `7500,00`, `7500.00` y `7500` sin ambigüedad (con coma, los puntos son miles) y `localize=True` los renderiza en formato español; `fecha_adquisicion` usa `DateInput(format='%Y-%m-%d')` o el navegador deja el campo vacío. El JS `static/js/vehiculo-costes.js` debe seguir siendo idempotente: `parseSpanish()` solo quita los puntos si hay coma (si no, multiplicaba por 100 en cada formateo). **Reparación de importes corruptos** (bug antiguo ×10.000): `python manage.py corregir_coste_vehiculo <matricula> --precio-subasta 7500 --tasas 400 --grua 250 [--tipo-iva 136.50]` corrige los importes y anula por contrapartida el asiento anterior y crea uno nuevo posteado (`--sin-asiento` para no tocar contabilidad).
- **Workshop stock** in via `CompraMaterial`. **Alta de material en un solo paso**: la línea de la factura identifica el material **por nombre** (`material` es un `CharField` con `datalist`; ya no es un desplegable de materiales). Si el nombre coincide con uno existente (`nombre__iexact`) se reutiliza y suma stock; si no, `resolver_material()` lo crea **dentro de la transacción** con la `unidad` indicada (obligatoria solo para materiales nuevos) y el precio de esa compra. El inventario (`/erp/taller/materiales/`) es de consulta/edición: se retiraron los botones «Nuevo Material» y «Registrar Compra» (la ruta `material_create` sigue existiendo pero sin acceso desde la interfaz). `save()` updates stock + invoice amounts, but the view explicitly calls `crear_asiento_contable()` and posts it if balanced (the model doesn't auto-post). Crédito by default: asiento DEBE 300/310/320/330 + 472 / HABER 410, no bank movement. `forma_pago` (FK `CuentaContable`, limited to 410/570/572) switches to contado: 572 → HABER 572 + EGRESO via `crear_movimiento_banco()` (saldo pre-validated in `views_material.py` before the atomic block); 570 → caja, no bank movement. The whole factura is one atomic block — any error rolls back every line. Crédito purchases can be paid automatically (migration `workshop/0007_compramaterial_pago` adds `pagado`/`fecha_pago`/`cuenta_pago`; the create form's "Pagar ahora" checkbox, or later via views `compra_pagar`/`compra_deshacer_pago`, POST-only + admin-only): `crear_asiento_pago()` is idempotent (DEBE 410 / HABER 570-572, EGRESO via `crear_movimiento_banco()` only for 572; raises on contado purchases) and `_anular_asiento_pago_compra()` reverses it Ley-Antifraude style (counter-entry + deletes the linked EGRESO). "Pagar ahora" only applies to crédito (ignored on contado) and pre-validates the bank saldo before the atomic block.
- **Compras: historial, resumen y corrección**. `CompraMaterial.factura_grupo` (uuid, migración `workshop/0008`) agrupa las líneas de una misma factura. Rutas: `compras/` (historial agrupado con totales), `compras/<grupo>/` (hoja resumen: datos, líneas, asientos con sus movimientos y PDF) y `compras/<grupo>/editar/` (corrección). El alta acepta el botón `guardar_y_otra` (vuelve al formulario vacío) y, si no, redirige al resumen. La corrección llama a `CompraMaterial.revertir(user)` por línea (devuelve la cantidad al stock, anula **por contrapartida** el asiento de compra y el de pago y borra el EGRESO) y vuelve a registrarla en el **mismo grupo** con `_crear_lineas_factura()`: los asientos viejos quedan ANULADOS y con su reversión, así que la traza se conserva (Ley Antifraude: nunca se borran asientos). El PDF se lee a bytes antes de borrar las filas y se vuelve a adjuntar; si el archivo ya no existe en disco (disco efímero de Render), la lectura captura `FileNotFoundError`/`OSError` y la corrección continúa **sin adjunto** (con aviso al usuario). Si el usuario **sube un PDF nuevo** en la corrección, se usa ese directamente y no se lee el anterior. Ojo con el nombre: `django-cleanup` borra los archivos de las filas eliminadas al **confirmar la transacción**, así que `_nombre_pdf_sin_colision()` renombra el PDF nuevo (`_corregida_xxxxxx`) cuando reutiliza el nombre del antiguo; sin eso, la limpieza diferida borraba también el archivo recién subido y la factura quedaba con «PDF no disponible». El resumen solo muestra «📎 Ver PDF» si `default_storage.exists()` confirma que el archivo está ahí; si no, muestra «PDF no disponible». `CompraMaterial.fecha_vencimiento` (migración `workshop/0009`) es **obligatoria en el formulario cuando la compra es a crédito y no se marca «Pagar ahora»** (`CompraFacturaForm.clean`); el historial la marca en rojo («Vencida») y el resumen muestra una banda de aviso cuando `< hoy` y sigue sin pagarse.
- **Accounting entries are not auto-generated by `save()`**. Models expose a `crear_asiento_contable()` method that views/services call explicitly. Bank movements are likewise created by explicit calls (`registrar_movimiento_banco()` or `apps.bank.services.crear_movimiento_banco()`), not signals.
- **`GastoEstructura` auto-posts** when balanced (like `InversionInicial`). Other auto-creations: warranty cost transfer (`apps/expenses/services.py:transferir_coste_garantia()`, from `apps/warranty/views.py`); the monthly SS task (`generar_cuotas_seguridad_social`, `apps/accounting/tasks.py`) instead creates a BORRADOR 642/572 with no movements (not auto-posted). Pending in 410 until `pagado=True`, which auto-generates the payment asiento (`PagoGastoEstructura`: DEBE 410 / HABER 570-572, idempotent) + EGRESO via `crear_movimiento_banco()` (572 only, never caja 570). Unmarking reverses it (`AnulacionPagoGasto` + `_anular_asiento_pago`, `apps/expenses/views.py`, which also deletes the linked EGRESO).
- **61x counts in the result** (PyG `variacion_existencias` + Balance `resultado_ejercicio`): OT completion credits 611 for capitalized labor (DEBE 310) and operario payroll is never posted, so excluding 61x descuadra the Balance by the labor amount.
- **Vehicle purchase**: `save()` auto-calculates `coste_inicial` from the cost fields. The create/update view then explicitly calls `crear_asiento_contable()` and `registrar_movimiento_banco()`.
- **Sales payments** (`CobroFraccionado`, migration `sales/0006`): plazos go PENDIENTE→RECIBIDO; `cobro_recibir` calls `CobroFraccionado.recibir()` which generates the asiento. `VentaVehiculo.pagada` auto-flips when `total_cobrado >= precio_venta` (recomputed from RECIBIDO cobros).
- **Stray git-tracked logs**: `backend/server_out.txt` / `server_err.txt` are leftover local runserver output dumps, not config — ignore or delete them. `backend/test_staging.db` is a stray SQLite file (git-ignored), same treatment.
- **Windows console encoding**: repo files are UTF-8 Spanish; PowerShell 5.1 `Get-Content`/console output shows mojibake accents (`García` → `García`). Cosmetic only — don't "repair" the files.
- **Docker Postgres password**: compose substitutes `POSTGRES_*`/`SECRET_KEY` from shell vars or root `.env`; this machine runs `--env-file .env.production` (`POSTGRES_DB=eurocar_prod`, password ≠ compose default `eurocar_dev_2024`). The `pgdata` volume keeps the password from first init — recreating containers with a different env breaks backend auth (FATAL: password authentication failed). Always start/restart with the same env file.
- **Dev nginx** mounts only `docker/nginx/default.conf` — never the whole dir (`prod.conf` is for `docker-compose.prod.yml`, needs SSL certs in `docker/nginx/ssl/`, and crashes dev nginx without them). After recreating `backend`, `docker-compose restart nginx` to re-resolve the upstream IP (else 502).

## Production Deploy

Deployed on **Render** (Python runtime, not Docker). Self-hosted alternative: `docker-compose.prod.yml`. Render build: `pip install -r requirements.txt && python manage.py collectstatic --no-input && python manage.py migrate`. Start: `gunicorn config.wsgi:application --bind 0.0.0.0:8000 --workers 2 --timeout 120`.

- **Two deploy targets**: `render.yaml` defines the **staging** service (branch `staging`, `DJANGO_SETTINGS_MODULE=config.settings.staging`). `master` is the main branch (`origin/HEAD` → `master`); production deploys from it via the Render dashboard (not in-repo, **no auto-deploy** — push alone does not deploy production). The current repo branch is `staging`.
- **Render (situación actual)**: staging está desplegado en **https://staging.rogil.co** — servicio `eurocar-staging` (rama `staging`, plan free, región Fráncfort), base `rogil-db-staging` (gratuita, caduca a los ~30 días) y media local/ephemeral. **No hay producción**: la cuenta de Render no tiene método de pago y el bloque de producción de `render.yaml` está comentado; reactivarlo cuando exista tarjeta. Los servicios antiguos `eurocar-jdx2.onrender.com` / `eurocar-staging-jdx2.onrender.com` **ya no existen** (404): no usarlos ni buscarlos. El dominio `rogil.co` está en Cloudflare (Namecheap como registrador); `rcarrogil.com` queda para cuando se libere.
- **`docker-compose.prod.yml` (self-hosted)** requires: `.env.production` (see `.env.production.example` — must include `DJANGO_SETTINGS_MODULE=config.settings.production`, else `wsgi.py`/`celery.py` default to development), SSL certs in `docker/nginx/ssl/` (`fullchain.pem` + `privkey.pem`), `docker/nginx/prod.conf` (HTTP→HTTPS redirect). Backend runs `migrate` + `collectstatic` at boot; SPA is built inside `backend/Dockerfile.prod` (no `vue_data` volume — an empty named volume would shadow the built SPA).
- **Env vars by environment**: dev = `backend/.env` (`SECRET_KEY` mandatory). Staging/Render = `SECRET_KEY`, `DATABASE_URL`, `DEBUG`, `ALLOWED_HOSTS` (in `render.yaml`); no `REDIS_URL`/`AWS_*`. Production/Render (manual §12.5-12.6) = same + `AWS_*` (R2 media) + `EMAIL_*` (SMTP); `REDIS_URL` optional (graceful fallback). Opcionales para cambiar de dominio sin tocar código: `CSRF_TRUSTED_ORIGINS` y `HSTS_PRELOAD=false` (ver `PRODUCCION.md` §7).
- **Staging media**: `staging.py` no exige bucket (por defecto, disco local efímero) pero **sí activa S3/R2 si existe `AWS_STORAGE_BUCKET_NAME`**, para probar la persistencia antes de producción. Mientras no haya bucket, `SERVE_MEDIA_LOCAL=True` permite abrir los PDFs (se pierden en cada redeploy). The SPA artifacts (`backend/static/web/`) are committed, so the public catalog serves at `/` on staging/prod; keep `collectstatic` in the Render build (it copies `static/web/` into `staticfiles/web/` for `spa_index`).
- **WhiteNoise without manifest**: `STATICFILES_STORAGE = CompressedStaticFilesStorage` (staging + production) — intentional. The Vite `index.html` references assets by name (`/static/web/assets/...`); the manifest storage renames files and would break the SPA. Django's own statics lose hash cache-busting (cosmetic).
- **Staging quirks** (`config/settings/staging.py`): Celery tasks run eagerly/sync — don't assume a Celery worker or Redis-backed cache there.
- **Auto-Deploy**: push to the service's configured branch. If a push doesn't go live, click **Manual Deploy → Clear build cache & deploy**.
- **Ephemeral filesystem**: uploaded media lost on redeploy. Persist via R2 (set `AWS_STORAGE_BUCKET_NAME` to activate `storages.backends.s3.S3Storage` in `production.py:33`). Bucket must be public (`AWS_QUERYSTRING_AUTH=False`).
- UptimeRobot pings `https://<app>.onrender.com/api/ping/` every 10 min to avoid cold starts (`/api/ping/` returns plain-text "OK", no DB access — also Render's `healthCheckPath`). DB backed up daily by `.github/workflows/backup.yml`.
